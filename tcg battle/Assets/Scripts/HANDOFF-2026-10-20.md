# Handoff note — audit + validation day (2026-10-20)

Written after a full audit + live validation pass. **No game code or assets were changed this session.**
This note records what was verified, what the unfocused-stall really is, and how to re-validate quickly.

## 1. Bot turn stall when the Unity Editor is unfocused — root cause (measured, not guessed)

Symptom reported by a previous session: bot turns seemed to freeze/shall not advance while the
Editor window was unfocused.

**Measured conclusion: this is Unity Editor background behavior, not a gameplay bug.**

- Unity 2022.3.62f3, `ProjectSettings.asset` has `runInBackground: 0`, and `EditorSettings.asset`
  has no Interaction Mode override (=> default "Default (Throttled)").
- While Play mode was running and the Unity window was **not** the foreground window:
  - `Time.frameCount` and `Time.unscaledTime` did not advance at all across a 10 s idle window
    (0 frames, 0 unscaled seconds — not throttling, a full stop of the player loop).
  - Even incoming MCP tool requests that execute on the main thread do **not** pump the player
    loop ("u=", "f=" identical in samples taken around them).
- While focused, the same session ran at ~440 fps (vsync off) and the bot turn completed:
  bench play at ~0.7 s, attack at ~2.4 s ("Warga Desa mendarat 60 damage (2x)!"), turn
  handed back at ~3.2 s — exactly the designed `WaitForSecondsRealtime(0.7/1.2)` pacing,
  exactly once, no duplicate turns or stalls.
- Also reproduced mid-coroutine: a bot turn left in its first wait (temporarily set
  `actionDelay=4.0`, then **reset back to 0.7**) never advanced while unfocused, and continued
  normally when focus returned (earlier in the session).

`WaitForSecondsRealtime` was already the correct choice for pacing (previous session switched it in);
it protects against *scaled time* crawl but cannot manufacture frames when the player loop does not run.

**How to validate again (fast):**
1. Start Play mode, keep the Unity window focused -> bot turns must progress normally.
2. Click to another app mid bot turn -> bot visibly waits; click back into Unity -> bot resumes
   at the next wait boundary, completes its turn normally.
3. Optional environment fix (a user preference, not a code change): Unity Preferences → General →
   Interaction Mode → "Monitor Refresh Rate" (or a pinned FPS), and/or Player Settings →
   "Run in Background" = true (affects built players; Editor behavior still governed mainly by
   Interaction Mode). This was NOT changed for you.

## 4. Tooling notes for the next session (saves you an hour)

- The Unity MCP `execute_code` executes C#6 via CodeDom inside a method body:
  - No `using` directives; fully-qualify everything.
  - `FindObjectOfType(...)` is typed `UnityEngine.Object` — cast to `Component` before calling
    `GetComponentInChildren`.
  - `List<CardInstance>` casts to `IEnumerable<object>` (covariant) — **NOT** to `IList<object>` (that
    silently returns null and then NREs).
- `execute_code` blocks the main thread for its duration — never sleep inside a probe to "watch"
  the loop; the player loop only advances *between* tool calls while Unity is focused. Sample
  across separate calls with client-side gaps instead.
- Reflection shortcuts used all session (all public members):
  `stt.Battle`, `battle.{Phase,StatusMessage,Player,Bot}`, `battle.{ConfirmStartingActive,
  EndPlayerTurn,Attack,PlayCardFromHand,CanAttack,BotPlayToBench,BotAttack,CanBotAttack,BotEndTurn,Restart}`.

## 8. Stage 3 — card inspection preview (2026-10-20, late night) — implemented & validated

Per the user's revised stage order, Stage 3 = card inspection preview (the "active-card idle" idea from the original list is deferred — bring it up with the user before building it).

Files changed: **NEW** `Assets/Scripts/UI/CardInspectPreview.cs`; `Assets/Scripts/UI/HandController.cs`; `Assets/Scripts/UI/BattleUI.cs` (UI only — no listener or rule changes).

Design:
- `CardInspectPreview`: self-contained code-built overlay panel under `SafeRoot`, last sibling so it draws over the board. Shows: large art (preserveAspect), name, live HP bar (`HpColor` green→amber→red), ATK row (gold cost chip + "ATK n · attackName"), element chip + icon, and the effect note **only when the data actually carries one** (`attackEffectText`; supports have no description text in the data, so nothing is invented — supports show name/art/PASIF and omit HP/ATK/element rows; empty `attackEffectText` (e.g. Siluman Babi/Pak Karta) also omits the row).
- Never intercepts input: `CanvasGroup.blocksRaycasts=false, interactable=false`, raycastTarget=false on every graphic (bridge-proven: `RaycastAll` at the panel's own screen point = 0 hits).
- Show = 0.12s fade + 0.94→1 scale; content swap while open does not restart the fade; hide = 0.10s reverse. Unscaled time (works during pauses).
- Placement: panel bottom = 14px above the source card's **world top edge** (hover lift/rotation respected), x centered on the card, clamped inside `SafeRoot` with 10px pad — never clipped, notch-safe, recalculated on `OnRectTransformDimensionsChange`.
- Card-following discipline: `HideIfCard(instance)` matches by `CardInstance` identity — overlapping hand cards, two same-ID copies (e.g. two SB), and exit-after-enter races all resolve correctly; sweep order independence proven in both orders.
- Wiring: hand side — `HandController.OnViewHover` drives Show/HideIfCard; guard in `Sync()` hides when the previewed card leaves the hand (confirmation, discard). Opponent side (addendum) — `BattleUI.BindSlot/BindBenchRow(botInspect:true)` wires `Hovered` for `botActiveView` + `botBenchViews[]` with the same `-=`/`+=` idempotent pattern as `Clicked`; `OnBoardHovered` driver; **face-down cards never open the preview** (nothing hidden is revealed — bot hand/deck have no card views at all); refresh guard hides when the previewed bot card leaves the board (KO/promote/retreat); `ShowGameOver` clears preview + source. Player active/bench intentionally do NOT preview (opponent-only scope; their hover tint is the pre-existing Stage-1 CardView behavior).
- The panel is registry-scaled (built before the `UiRescaler` capture) and stays on the correct side: for opponent cards it lands wholly in the bot zone (panel bottom above the 0.6203 divider — buttons/status never covered, numerically asserted).

Bugs found & fixed during validation:
1. Same-frame exit→enter race: old code let the previous card's fade-out continue and the new card's content faded to invisible; `Show()` now always owns the fade (animates from current alpha).
2. Content leak: `EffectText` stayed active with stale text when switching a battle card → a support card. Every battle-only row now explicitly resets to hidden in `Bind()` before re-enabling per card data.
3. `HpFill` was created through a helper that auto-parents to the root → it stretched over the whole panel (visible as a big green egg in captures). Fixed by parenting into `HpBg` (also switched the two other reparent calls to the helper's parent parameter for one consistent pattern).
